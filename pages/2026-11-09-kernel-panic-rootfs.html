Kernel Panic: VFS: Unable to mount root fs on unknown-block(179,2)

自訂編譯 Linux 核心啟動於 Raspberry Pi (BCM2835) 開發板時，核心無法掛載 MMC/SD 卡的 ext4 根檔案系統並觸發 Panic。本文深入追蹤核心啟動命名空間初始化機制，分析驅動模組化與內建（Built-in）對 Early Boot 階段的致命影響。

模組一：問題現象與日誌重現 (Symptom & Log Dump)

開發板上電啟動後，U-Boot 成功加載核心 Image 與 Device Tree (bcm2835-rpi-b.dtb) 並將控制權轉交核心。然而 Linux 核心啟動約 2.3 秒後，日誌輸出中斷並印出死當回溯堆疊：

模組二：根本原因分析 (Root Cause Analysis)

裝置編號解析：unknown-block(179,2)

在 Linux 驅動主次設備號規範（Major/Minor Numbers）中，主編號 179 代表 MMC/SD 區塊設備控制器（/dev/mmcblk0），次編號 2 代表第二個磁碟分區（/dev/mmcblk0p2）。

核心標註 unknown-block，意味著核心目前的區塊設備子系統（Block Layer）中，完全沒有向核心註冊該主編號 179 的驅動實體，核心根本認不得這顆 SD 控制器！

「先有雞還是先有蛋」的驅動死鎖

檢查自編核心的 .config 設定檔，發現 CONFIG_MMC=m、CONFIG_MMC_BLOCK=m 與 CONFIG_EXT4_FS=m 被設成了可載入模組（Loadable Kernel Module）。

在沒有使用 initramfs / initrd 記憶體暫存碟的系統中，動態模組檔案（.ko）存放於磁碟分區上的 /lib/modules/。核心要掛載 rootfs 必須先有驅動，但加載驅動又必須先掛載 rootfs，造成死鎖直接崩潰。

Early Boot Sequence 核心開機時序分析：

1. kernel_init() → 核心進入 PID 1 初始化常式。

2. prepare_namespace() → 解析 bootargs (root=/dev/mmcblk0p2)。

3. mount_block_root() → 尋找 major=179 區塊設備，呼叫 get_gendisk()。

4. [FAIL] 查無 MMC Driver → 驅動尚未 insmod，bdev 指標為 NULL，觸發 panic()！

模組三：排查與修復步驟 (Step-by-Step Fix)

1 檢查 U-Boot 傳遞之開機參數 (bootargs)

在 U-Boot 命令列中輸入 printenv bootargs，確認設備路徑無拼寫錯誤且包含 rootwait（讓核心等待 MMC 總線枚舉完畢）： 

# U-Boot 開機參數正確範例
setenv bootargs "console=ttyAMA0,115200 root=/dev/mmcblk0p2 rootfstype=ext4 rootwait rw"
saveenv
2 修改 Kernel Kconfig 配置：將關鍵驅動強制改為 Built-in (=y)

執行 make menuconfig 或直接編輯 arch/arm/configs/bcm2835_defconfig，將 MMC 控制器與 ext4 檔案系統改為編譯進核心（=y 而非 =m）： 

--- a/.config
+++ b/.config
@@ -1945,8 +1945,8 @@
-CONFIG_EXT4_FS=m
+CONFIG_EXT4_FS=y
 CONFIG_EXT4_FS_POSIX_ACL=y
 CONFIG_EXT4_FS_SECURITY=y
@@ -3420,9 +3420,9 @@
-CONFIG_MMC=m
+CONFIG_MMC=y
 CONFIG_MMC_BLOCK=y
-CONFIG_MMC_BCM2835=m
+CONFIG_MMC_BCM2835=y
3 重新編譯核心並燒錄至開機分區 
# 交叉編譯 Kernel Image 與設備樹
make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- -j$(nproc) zImage modules dtbs

# 部署 zImage 至 SD 卡 boot 分區（fat32）
sudo cp arch/arm/boot/zImage /media/$USER/boot/kernel7.img
sudo cp arch/arm/boot/dts/bcm2835-rpi-b.dtb /media/$USER/boot/
sync

BSP 維護預防清單 (Checklist)

  • 根目錄儲存媒介驅動一律 Built-in：凡是 rootfs 所在的儲存晶片（eMMC、NAND、SPI-NOR、SATA）及其所屬的主機控制器驅動，不得編譯為模組 =m。
  • 檔案系統驅動一律 Built-in：若 rootfs 為 ext4、ubifs、squashfs，該 FS 模組必須設為 =y。
  • U-Boot bootargs 標配 rootwait：MMC/SD 卡開機必須加上 rootwait，避免主機控制器枚舉較慢時提前 panic。
  • CI/CD Defconfig Lint 檢查：在 GitHub Actions 或 Jenkins 建置腳本中加入 scripts/diffconfig 檢查，阻擋將關鍵啟動選項改為模組的 Pull Request。
