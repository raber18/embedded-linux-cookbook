I2C Transfer Timed Out 與 MPU6050 Probe 失敗 (-110)

在 Linux 5.10 平台掛載 MPU6050 慣性感測器驅動時，系統持續拋出 transfer timed out 錯誤（-110 ETIMEDOUT）。本文透過示波器實測 Open-drain 電氣特性，排查 PCB 缺少上拉電阻與 Device Tree 內部弱上拉缺失問題。

模組一：問題現象與日誌重現 (Symptom & Log Dump)

載入 inv-mpu6050-i2c 驅動模組時，核心日誌重複噴出超時訊息，感測器 probe 失敗：

dmesg -w Output

[   15.426000] mpu6050 1-0068: probe of 1-0068 failed with error -110
[   15.431200] inv-mpu6050-i2c: probe of 1-0068 failed with error -110

模組二：根本原因分析 (Root Cause Analysis)

I2C 開漏極 (Open-Drain) 電氣拓撲

I2C 匯流排標準（NXP UM10204）規定 SDA 與 SCL 訊號線必須採用開漏極（Open-Drain）架構。晶片內部晶體管只能將線路下拉至低電平（0V），無法主動驅動高電平。

示波器量測 SCL/SDA 探針顯示電位持續為 0V（低電平鎖死）。由於匯流排無任何上拉源，I2C 控制器發送 START condition 後等待訊號線釋放高電平，但始終處於 Low 狀態，核心控制器驅動觸發逾時（ETIMEDOUT = 110）。

軟體 Device Tree Pinctrl 遺漏

查驗設備樹 pinctrl-0 設定，發現 I2C 引腳節點只配置了 pinmux 多路複用，未開啟晶片內建的上拉偏壓設定（bias-pull-up 或相應暫存器）。

外圍感測器模組 PCB 端亦未焊接外部上拉電阻，造成線路處於浮接/偏低狀態，致使軟體與硬體皆無上拉來源。

I2C 上拉電阻阻值精確計算公式

根據 I2C 匯流排規格，上拉電阻 $R_p$ 的範圍受限於匯流排負載電容 $C_b$ 與最大容許上升時間 $t_r$：

最小阻值限制（避免驅動端吸入過大電流）：
$$R_{p(\min)} = \frac{V_{DD} - V_{OL(\max)}}{I_{OL}}$$

以 $V_{DD} = 3.3\text{ V}, V_{OL} = 0.4\text{ V}, I_{OL} = 3\text{ mA}$ 計算：$R_{p(\min)} = \frac{2.9}{0.003} \approx 966\ \Omega$

最大阻值限制（受上升時間 $t_r$ 與總電容 $C_b$ 限制）：
$$R_{p(\max)} = \frac{t_r}{0.8473 \times C_b}$$

標準模式 ($100\text{ kHz}$) 下 $t_r \le 1000\text{ ns}$，若 $C_b = 200\text{ pF}$：$R_{p(\max)} \approx 5.9\text{ k}\Omega$。故最佳推薦值取 $4.7\text{ k}\Omega$。

模組三：排查與修復步驟 (Step-by-Step Fix)

1 硬體層修復：外接 $4.7\text{ k}\Omega$ 上拉電阻

在 SDA 與 SCL 接腳分別串接一顆 $4.7\text{ k}\Omega$（0402 或 0603 封裝）電阻至系統 $3.3\text{ V}$（VCC）電源軌。用示波器確認未通訊時 SCL/SDA 電位維持在穩定的 $3.3\text{ V}$。

2 軟體 Device Tree (DTS) 修復：加入內部上拉與節點宣告

修改板級 Device Tree 文件（如 arch/arm/boot/dts/soc-board.dts），在 pinctrl 節點開啟 bias-pull-up 並綁定感測器節點： 

--- a/arch/arm/boot/dts/soc-board.dts
+++ b/arch/arm/boot/dts/soc-board.dts
@@ -82,6 +82,7 @@
 	i2c1_pins: i2c1-pins {
 		pinmux = <PIN_I2C1_SDA>, <PIN_I2C1_SCL>;
+		bias-pull-up;
 	};
 };
 
@@ -105,4 +106,12 @@
 &i2c1 {
 	pinctrl-names = "default";
 	pinctrl-0 = <&i2c1_pins>;
 	status = "okay";
+
+	mpu6050@68 {
+		compatible = "invensense,mpu6050";
+		reg = <0x68>;
+		interrupt-parent = <&gpio1>;
+		interrupts = <14 IRQ_TYPE_EDGE_RISING>;
+	};
 };
3 重新編譯 Device Tree Blob (DTB) 並重啟 
# 編譯設備樹
make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- dtbs

# 替換 Target 開發板上的 DTB 檔案
scp arch/arm/boot/dts/soc-board.dtb root@192.168.1.50:/boot/
ssh root@192.168.1.50 "sync && reboot"

硬體與 BSP 審查清單 (Checklist)

  • 硬體線路審查：所有掛載於 I2C 匯流排的 Peripheral 模組，必須確認硬體電路圖上至少存在一組外部上拉電阻（建議 2.2kΩ ~ 4.7kΩ）。
  • 內部弱上拉限制注意：SoC 內部弱上拉阻值通常較大（約 40kΩ ~ 100kΩ），在高速傳輸或線路電容較大時上升時間會嚴重失真，不可完全依賴內部 Pull-up 代替外部電阻。
  • 示波器波形驗證：除錯時務必先確認 idle 狀態為 high，並測量 SCL/SDA 方波之上升時間（Rise Time）是否符合協議規範。
