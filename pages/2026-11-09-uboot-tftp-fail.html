U-Boot TFTP 下載逾時與乙太網路 PHY Reset 失敗分析

在 U-Boot 開發階段使用 TFTP 網路下載 Linux 核心與 DTB 映像時遭遇 PHY reset timed out 伴隨 link down，後續重試噴出 File not found。本文完整剖析乙太網路 PHY 硬體復位時序要求、U-Boot 環境變數網段設定以及 Host 端 TFTP Daemon 權限機制。

模組一：問題現象與日誌重現 (Symptom & Log Dump)

開發板進入 U-Boot 命令列後執行 TFTP 下載核心指令，終端機回傳 PHY 晶片重置逾時，網路連線失敗，並於重試時報錯中斷：

U-Boot Console Dump
PHY & TFTP Timeout 
=> tftp 0x82000000 zImage
ethernet@01c50000: PHY reset timed out
ETH: link down
TFTP error: 'File not found' (1)
Not retrying...
Retry count exceeded; starting again
missing or malformed file: 'zImage'

模組二：根本原因分析 (Root Cause Analysis)

1. PHY 硬體 Reset 時序不足

乙太網路 PHY（如 Realtek RTL8211 或 Microchip KSZ9031）硬體規格規定，硬體重置腳位（reset-gpios）拉低時間至少需 10ms，且在釋放重置後，晶片內部 PLL 振盪器與類比前端需約 30ms ~ 50ms 穩定時間。

原 Device Tree 僅設定 phy-reset-duration = <10> 且無 post-delay，U-Boot 在 PHY 尚未恢復時即透過 MDIO 讀取暫存器，造成 Timeout 與 link down。

2. 網路參數與 Host IP 漂移

開發板 U-Boot 靜態設定的 serverip 為 192.168.1.100，但開發用 Host PC 由於路由器 DHCP 重新配發租約，實際 IP 已漂移為 192.168.1.120。

兩者 IP 網段或主機位址不匹配，導致 U-Boot 發送 ARP 請求無人應答，無法建立 UDP TFTP 連線。

3. TFTP 根目錄權限隔離

Host 端安裝的 tftpd-hpa 服務預設以非特權使用者（tftp）執行。

編譯完成的 zImage 被以 0600 (root:root) 複製進 /var/lib/tftpboot/，TFTP 伺服器無讀取權限，在 RFC 1350 協議中回報 Error Code 1（File not found / Access violation）。

模組三：排查與修復步驟 (Step-by-Step Fix)

1 修改 Device Tree：延長 PHY Reset Duration 與 Post Delay

修改板級 Device Tree 中乙太網路 MAC / MDIO 節點，將 Reset 脈衝時間拉長至 50ms，並加入 30ms 的復位後延遲： 

--- a/arch/arm/dts/sun8i-h3-board.dts
+++ b/arch/arm/dts/sun8i-h3-board.dts
@@ -112,6 +112,8 @@
 &emac {
 	phy-handle = <&ext_rgmii_phy>;
 	phy-mode = "rgmii-id";
-	phy-reset-duration = <10>;
+	phy-reset-duration = <50>;
+	phy-reset-post-delay = <30>;
 	allwinner,reset-gpio = <&pio 3 14 GPIO_ACTIVE_LOW>; /* PD14 */
 	status = "okay";
 };
2 校正 U-Boot 網路環境變數並 Ping 驗證

確認 Host 端當前 IP（ip a 顯示為 192.168.1.120），在 U-Boot 設定同一網段 IP 並儲存： 

# 設定板子 IP 與 TFTP Server IP
setenv ipaddr 192.168.1.50
setenv serverip 192.168.1.120
setenv netmask 255.255.255.0
saveenv

# 測試雙向網路連通性
ping 192.168.1.120
3 修正 Host 端 TFTP 服務檔案權限

開放 TFTP 根目錄檔案之 Other 讀取權限，確保 tftpd-hpa 常駐進程可正常讀取檔案： 

# 賦予檔案全域讀取權限
sudo chmod 644 /var/lib/tftpboot/zImage
sudo chmod 644 /var/lib/tftpboot/*.dtb

# 重啟 TFTP 服務
sudo systemctl restart tftpd-hpa
sudo systemctl status tftpd-hpa

BSP 與除錯環境防呆清單 (Checklist)

  • PHY Datasheet Reset 時序審查：繪製或移植硬體時，務必參閱 PHY 晶片手冊中「Power-On and Reset Characteristics」，設定充足的 Reset hold time 與 Recovery time。
  • Host IP 靜態分配：開發用主機建議設定固定靜態 IP 或於路由器綁定 MAC 位址，避免 DHCP 重新配發導致 U-Boot 與 NFS/TFTP 中斷。
  • 自動化構建權限規範：在 build 腳本或 Makefile 加入 install -m 644，確保拷貝至 tftpboot 的映像具備全域可讀權限。
